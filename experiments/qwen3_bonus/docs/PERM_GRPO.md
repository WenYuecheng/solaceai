# 面向需求满足与具体共情的单卡GRPO实验

本实验在Qwen3-4B本地回答链路上，用通用偏好与可验证用户要求共同构造奖励，在20元以内完成一次回答LoRA训练。原256条训练题、32题开发集、80题测试集和历史模型均继续使用。

2026-10-25已完成64步完整训练及四模型80题统一评测。最终第64步模型四维质量均分达到 **3.253**，全面超越基座（3.169）、GRPO32（3.212）和GRPO32＋SFT（3.203）；对基座偏好胜率达 **56.25%**（27胜36平17负）。在倾听与心理支持核心40题场景中，语义完成率达50.0%（20/40）、均分达3.125，且在高分共情峰值回答上展现出显著优势。完整评分、区间、换序复评和部署选择口径见[本轮完整报告](PERM_EVALUATION.md)。

方法借鉴[PERM的调和组合思想](https://arxiv.org/html/2601.10532v2)。Skywork提供通用偏好，程序检查约束用户明确要求的结构和引用，独立的四维语义评价检验情绪理解、共情表达、需求满足和整体质量。

## 数据与配方

原题面、对话、ID、切分及JSONL字节保持一致。新数据清单记录原版本指纹和新增评价标注。192条只有字数检查的训练题使用偏好奖励，字数检查独立记录。

偏好分为 `sigmoid((raw_rm - median) / max(IQR, 0.1))`。有可验证要求时，以偏好分与要求通过比例的调和平均作为主奖励；无适用检查时使用偏好分。有效回答扣除 `0.1 × repetition_ratio`，明确无效回答为−1。同组两条有效回答均完全未通过适用检查时，训练奖励统一为0并单独记录。

训练固定rank8／alpha16、q/v模块、种子3407、提示批量4、每题2个候选、mini batch配置4、micro batch 1、学习率5e-6、Actor KL 0.02，输入768／回答256／总长1024，一个epoch最多64步。优势由verl 0.5.0原生GRPO计算。依赖继续使用vLLM 0.8.5和torch 2.6.0。

## 奖励模型与训练前证据

候选为固定版本的Skywork-Reward-V2-Qwen3-1.7B和0.6B。两个完整模型均已在本机按官方SHA256校验；1.7B已单独传到无卡服务器，0.6B复用原服务器文件。

本机真实CPU校准的预期标签在评分前固定，最终报告保留逐对原始分数和四种奖励组合：

| 候选 | 20对排序 | 任务交付8对 | 状态 |
|---|---:|---:|---|
| 1.7B | 19/20 | 8/8 | 通过校准门槛 |
| 0.6B | 20/20 | 8/8 | 通过校准门槛 |

这些数据用于奖励方向与输入链路检查。当前校准样本上，四种奖励方法的排序方向一致；机制对照保留这一实际结果。训练后的改善由冻结开发集和测试集评价。

本机校准文件放在 `artifacts/perm-grpo-20261024/local-final/`。它们明确记录本机平台、线程、代码与模型指纹；服务器上的副本作为本机证据归档。目标服务器的CPU速度和内存资格在GPU分配后的同一次受监控运行中测量。

## 无卡部署与GPU启动

独立目录为 `/root/solace-perm-20261024`，运行时复用原锁定环境：

```text
/root/autodl-tmp/solace-qwen3/experiments/qwen3_bonus/.venv-gpu/bin/python
```

准备阶段保持无卡模式。上传的源码、数据和小型报告均有完整清单校验；旧基座与0.6B通过明确链接复用，1.7B单独存储，原模型与GDPO产物保留。

GPU分配后，启动命令必须带实际单价、计费粒度、开始计费时间和CPU准备费用。`perm_launch`自动执行以下顺序：独立预算监控 → 一次初始化Actor／Reference → 实测主机内存 → 依次运行目标CPU校准 → 选择并冻结奖励模型 → 在同一组worker上训练。首次参数更新前完成选择，恢复时保持已冻结配方。

优先使用32GB显存，并为CPU卸载与1.7B评分配置充足主机内存，建议64GB。实际准入保留20%有效主机内存，并检查评分预计费用是否在可用训练费用的25%以内；1.7B不适合时按审计记录采用0.6B。

```sh
cd /root/solace-perm-20261024
/root/autodl-tmp/solace-qwen3/experiments/qwen3_bonus/.venv-gpu/bin/python \
  -m experiments.qwen3_bonus.perm_launch \
  --hourly-rate "$ACTUAL_HOURLY_YUAN" \
  --billing-quantum-seconds "$ACTUAL_QUANTUM_SECONDS" \
  --rental-started-at "$ACTUAL_RENTAL_START_ISO8601" \
  --preparation-cost-yuan "$ACTUAL_PREPARATION_YUAN" \
  --gpu-memory 0.65 \
  --shutdown-script-sha256 0358e83eeeaf542aa98f64ba9e339c91df46f1e025892d52dba159f4fb1cf027 \
  --wait
```

CPU准备费用从20元总额中扣除；GPU初始化阶段设置预算上限，保存至少预留2元和120秒。预算、64步或技术停止条件先到即停止。完整检查点在每8步和正常停止时原子保存，小型LoRA快照全部保留。根据用户2026-10-25的明确要求，PERM入口始终保留已分配实例：独立watchdog在训练无日志时仍按截止时间停止训练进程，正常结束和报错均不执行平台关机，实例由用户管理。`watchdog.json`中的`shutdown_argv`必须为`null`，运行清单记录`instance_shutdown_policy=preserve_user_allocation`。

本次32GB实例初始化时采用`gpu_memory=0.65`后完成生成缓存准入。训练结束后，用户另行明确授权在GPU真实推理、完整检查点校验及9快照本机回传后关机；已执行并由平台控制台确认“已关机”。本轮费用估算6.45元（含4元前期与旧尝试预留），没有新增租卡。自动巡检已删除。

## 选模与成果

80题统一评测比较基座、GRPO32、当前GRPO32＋SFT和新模型（第64步），统一量化基座、模板、温度0和256-token上限。

最终评测显示第64步在四维均分（3.253）上超过全部对照模型，对基座偏好率达56.25%，在倾听与支持核心场景中表现优异。当前降级配置指向 `artifacts/adapters/solace-response-perm-grpo64/`，原GRPO32＋SFT仍保留在 `artifacts/adapters/solace-response/`。

报告保留胜／平／负、`(胜+0.5×平)/80`、语义完成率、四维均分、严重问题类别、20%换序复核，以及真实的训练时间、费用、曲线和回答实例。对照历史模型的结果对应最终配方的实际效果。

无卡验收记录与最终源码指纹见 `artifacts/perm-grpo-20261024/READY_FOR_GPU.json`；它与真实训练结果分别保存。
