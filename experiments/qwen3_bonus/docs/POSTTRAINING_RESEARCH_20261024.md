# Qwen3 降级回答：面向实际效果的后训练选型

检索与代码核查日期：2026-10-24。约束：保留 Qwen3-4B、双 LoRA 的部署形态，尽量复用 verl / vLLM；训练预算为单卡 RTX 3090 24GB 或 vGPU 32GB。本文完成研究与方案评估，未启动租卡、训练或模型替换。

## 结论与推荐路线

值得重训回答 LoRA。最有希望产生可用收益的路线是： **领域偏好数据与任务完成度 → 质量筛选 SFT → 使用可信分项奖励的小规模 RL → 按留出集效果选择是否保留 RL。**

GRPO 没有因年份而失去使用价值；Dr.GRPO 也不是预定答案。首轮现代方法候选是 **GDPO** ，因为它处理本项目实际存在的多目标问题；保留标准 GRPO 作为同奖励、同预算对照。Dr.GRPO 式去偏可作为额外诊断项，SAPO / GSPO 暂不优先。最终允许质量筛选后的 SFT 成为部署结果，如果它在目标任务上表现更好。

可形成的贡献主线是： **在云端不可用和单卡训练预算下，让本地回答适配用户意图、可用证据与工具能力，在倾听质量、完整交付和响应成本之间取得可复现的收益。** 研究价值由新机制和受控实验支持；采用已有优化器、分项奖励或条件长度奖励本身不作为原创算法声明。

## 1. 项目的真实起点

### 已核对的实现

- 基座：`Qwen/Qwen3-4B-Instruct-2507`；0.6B 是 Skywork 奖励模型的尺寸。
- 框架：`verl==0.5.0`、`vllm==0.8.5`、`torch==2.6.0`。
- 回答 RL：BF16 LoRA，rank 8 / alpha 16，q_proj / v_proj，n=2，prompt batch=1，32 个优化步；CPU 上冻结奖励模型。
- 奖励：`sigmoid(raw_rm) - 0.2 * repeat_ratio`，少数正则匹配的无效输出给 -1。当前没有独立的任务完成、证据忠实或多视角共情奖励。
- 当前部署回答适配器：GRPO32 之后又做 84 步 SFT。新路线需要共同的 SFT 起点，才能比较 RL 方法。

证据：`models.py`、`requirements-gpu.in`、`training.py`、`rewards.py`、`docs/REPORT.md`。

本项目 n=2 且使用样本标准差。当两条奖励不同且差值显著大于 epsilon，归一化优势约为 ±0.707，大小几乎不反映奖励差距。因此小差异可能产生强更新。关闭 std 后优势变为 ±奖励差/2；在当前饱和区可能变得很小。 **更换归一化和校准奖励应联合评估。** 这是由代码和公式推导的机制解释，尚非重训后的效果结论。

## 3. 推荐的具体训练路线

### 第一步：把“好回答”变成可学习的目标

用领域样本和偏好对覆盖以下行为，保留完整对话级切分：

1. 用户只想倾听：理解已知事实、尊重不想要建议的意愿，避免凭空解释动机。
2. 用户提出明确任务：实际交付消息、计划、步骤等内容；不能只答“我可以帮你”。
3. 用户提供证据：使用材料支持的结论和正确引用；没有材料时不生成虚构来源。
4. 降级能力约束：知道当前能否检索、调用工具或联系外部服务，回答与真实能力相符。

从 PERM / ESCRAG-R1 借鉴多视角偏好筛选：优先保留需求满足、内容正确、支持表达共同较好的样本。先审核数据许可与中文适用性，按部署的256-token预算建立可完整交付的样本。若需要更长的任务响应，单独试验该场景的预算，统一比较条件。

使用现有 SFT 流程训练共同起点，保留 rank8/qv。教师生成或评审可以离线进行；若使用外部模型，应记录模型身份、调用条件与样本来源；不能把离线教师打分缓存冒充新 rollout 的在线奖励。

### 第二步：先验证奖励排序，再选择 RL

建议记录四组信号：需求满足/任务完成、支持质量、证据与能力边界、重复与成本。规则处理明确可验证的项目，模型评价语义质量；不把“字数多”“有三个步骤”当作任务完成。

安全与虚构工具承诺作为独立约束和淘汰条件，不能由文风或长度奖励补偿。短回答奖励只在任务完成和内容合格后生效。这种条件奖励在 GDPO §3.2 已有相关研究，不作为新发明。

在新的校准对上检查分项排序、饱和比例、组内方差和冲突率。现有 Skywork 0.6B 只有通用单分头，不能通过改字段名获得四种领域能力。可先保留它作为辅助分，并使用规则/经过校准的分项评价；必要时另做小型领域评分器的偏好适配。校准 reward 数值尺度的参数只由训练/校准集决定，测试集保持隔离。

 **最新方法的采用条件：** 分项能稳定区分好坏时试 GDPO；若分项质量尚未建立，先用筛选 SFT 或改进奖励的 GRPO。优化器选择由目标任务和成本共同决定。

### 第三步：用最小实验判断收益从哪里来

| 实验组 | 目的 |
|---|---|
| A：领域质量筛选 SFT | 得到强而便宜的共同基线 |
| B：A → GRPO，同一套新奖励 | 判断在线优化是否增加收益 |
| C：A → GDPO，同一组分项奖励 | 判断分项归一化是否增加收益 |
| D：胜出优化器 + 通用奖励对照 | 预算允许时分离领域奖励的贡献 |

当前部署 LoRA 和原始基座作为外部参照；不拿不同训练起点的历史结果替代 A/B/C。Dr.GRPO 式方案可按开发集现象替代一个探索项，不必全部训练。

先给 B/C 相同的小试预算，包含生成、奖励、更新和保存；选择有行为收益的路线延长训练。原32步入口硬限制和单epoch设置需先调整，不能在现有脚本上直接假设会执行数百步。新训练应扩大有效提示覆盖，不盲目重复原128条上下文。

评测主指标：用户请求实际完成率、倾听偏好、事实/证据一致性、能力承诺错误率；效率指标同时报告输出长度、完整性、热请求延迟及冷启动。统一解码与生成预算，准备新的留出对话，避免把已公开的24题直接变成调参目标。对最终候选进行换序对比、独立人工抽查及按对话汇总的不确定性估计。多随机种子用于复核最终选择；不要求把有限预算平均分给所有候选。

## 4. 单卡预算和现有框架怎么保留

### 保留的配置

- 4B 基座和静态回答 LoRA；分类 LoRA 本轮不需要重训。
- rank8 / alpha16、q_proj / v_proj、单卡、无 critic。
- vLLM 生成，micro batch=1，梯度检查点、已有 CPU offload。
- 首轮 n=2，输出上限与部署预算对齐；需要 n=4 时作为预算试验，不能默认“候选更多必然更划算”。

### 三条实现路线

1. **最小环境改动：** 保持锁定的 verl0.5.0 / vLLM0.8.5，先完成数据、SFT和标准GRPO的新奖励实验。这条路线已经能吸收领域论文的核心方法。
2. **引入GDPO：** 优先评估在实验目录增加显式 advantage 扩展及分项奖励传递，保持原依赖。需验证分项键、分组、mask、零方差、batch归一化和梯度尺度；不是更改 `adv_estimator` 一个字符串即可完成。[当前verl官方实现](https://verl.readthedocs.io/en/latest/_modules/verl/trainer/ppo/core_algos.html)已有GDPO，但不能据此认定0.5.0已有该实现。
3. **版本升级：** 若兼容扩展成本过高，使用隔离环境固定一组兼容的 verl / vLLM / torch 版本做冒烟验证，再决定迁移；不直接覆盖已能运行的环境。

Dr.GRPO的两项去偏机制在项目随附的0.5.0源码中可用：`norm_adv_by_std_in_grpo=False` 和 `loss_agg_mode=seq-mean-token-sum-norm`。严格复现还应保证固定归一化分母；[官方0.5文档](https://verl.readthedocs.io/en/v0.5.x/algo/grpo.html)的配方关闭KL。保留本项目KL=0.02时，应称带KL的去偏变体，并在对照中控制KL与更新尺度。

### 24GB / 32GB的现实安排

32GB优先复用现有4B BF16 LoRA路线。3090从同一模型、n=2、micro1开始，先测生成、奖励、更新和检查点保存整个周期。根据实测降低vLLM缓存预留和并发，并核查熵计算分块/重计算；必要时使用已验证的低显存配置。0.5.0随附actor配置存在相关熵选项，但需验证当前模型执行路径。

不能把现有分类QLoRA成功自动推导为verl的RL QLoRA兼容。若最终需要actor量化，应单独验证训练、vLLM权重同步和导出，不作为未测试的默认承诺。

资源证据存在口径差异：实例记录为32760MiB；历史训练指标报告allocated最高34.269、reserved最高34.480（字段名gb），与实例标称不一致，CPU指标也不是明确的本进程RSS。因此这些数值不能直接用于3090容量预测。后续小试同时记录设备总量、进程占用、峰值统计定义与主机内存。

运行规划依据实测步耗时、启动和保存时长。合理顺序是先用CPU/本机完成数据与奖励核查，把GPU时间集中在有效候选上。

## 5. 对“过时”和“创新”的判断

2026-08的ESCRAG-R1仍用GRPO解决情绪支持问题，2026-10的受控研究仍比较GRPO与筛选微调。因此，算法年份不决定项目价值。

本项目可以把最强证据组织为一条清晰贡献：面向云端故障的本地支持回答，按用户意图和可用能力设计训练目标，并在相同单卡成本下验证更好的需求满足与响应效率。领域偏好数据和GDPO等方法是支撑这条贡献的工具。

需要通过实验回答的关键问题是：新训练能否在保留倾听优势的同时提高实际交付，且在相同生成预算下减少不必要输出和能力越界。若SFT已达成目标，采用SFT；若GDPO或其他RL路线产生稳定增益，再选择该路线。成果以行为效果和可复现成本为准。
